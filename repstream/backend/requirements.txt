# RepStream — the single dependency file for the whole project.
#
# Lives in backend/ alongside .env and main.py, so this folder is self-contained
# and can be copied to a deployment target as-is. On the VM these same files sit
# at the root (veeva_ai_main/), which is why nothing in the code resolves paths
# by a fixed number of parent directories — see the note in app/config.py.
#
# Covers BOTH applications, which share one virtualenv:
#   backend/                the RepStream API
#   backend/ai_assistant/   the Datastream chatbot
#
# They previously had separate requirements files whose pins conflicted on every
# shared package — the backend pinned each one just below the chatbot's floor
# (fastapi 0.115.5 vs >=0.115.6, pydantic 2.10.3 vs >=2.11, scikit-learn 1.5.2
# vs >=1.8, pyodbc 5.2.0 vs >=5.3, openai 1.57.4 vs >=1.58.1). No single
# environment could satisfy both, which is why there were two venvs.
#
# Every entry below was checked against the code: each is either imported
# somewhere, or required at runtime by something that is (noted where that is
# not obvious). Floors are >= rather than == so one install serves both apps,
# and are set to the versions this project is actually running today.
#
#   cd backend
#   python -m venv venv
#   venv\Scripts\activate
#   pip install -r requirements.txt
#
# NOTE: torch alone is ~490 MB and transformers ~94 MB; a first install pulls
# roughly 1 GB. The assistant also downloads the all-MiniLM-L6-v2 model (~90 MB)
# from HuggingFace on its first query, so the host needs outbound internet then.

# middleware. It ships with fastapi today, but anything imported by name is
# declared — otherwise a future fastapi that stops vendoring it breaks us.
